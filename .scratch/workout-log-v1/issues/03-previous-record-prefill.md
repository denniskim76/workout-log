# 03: 지난 기록과 미리 채우기

**What to build:** 종목 기록 화면 위쪽에 그 종목의 지난 기록이 "지난 기록 · 3일 전 (10/4)"과 "60kg × 10 · 60kg × 8" 형태로 보이고, 처음 하는 종목이면 "첫 기록입니다"가 보인다. 입력 칸은 오늘 이 종목을 이미 했으면 방금 세트 값으로, 아니면 지난 기록의 첫 세트 값으로 미리 채워져서 대부분의 세트는 "기록" 버튼 한 번으로 끝난다. 무게는 +/- 2.5kg, 횟수는 +/- 1회 버튼으로 조절하고, 숫자를 탭하면 키패드로 직접 입력할 수 있다.

- [x] WorkoutLog가 미리 채우기 값(종목, 운동일)을 제공한다: 당일 그 종목의 가장 최근 세트 → 지난 기록의 첫 세트 → 빈 값 순
- [x] 기록 화면에 지난 기록이 날짜, N일 전, 세트 한 줄로 표시되고, 없으면 "첫 기록입니다"가 표시된다
- [x] 입력 칸이 미리 채워지고, 세트를 기록하면 다음 입력 칸이 방금 세트 값으로 바뀐다

- [x] 무게는 0 이상 소수, 횟수는 1 이상 정수만 기록되며 WorkoutLog가 잘못된 값을 거부한다
- [x] 테스트: 바로 전 세션에 종목이 없을 때 그 이전 세션을 찾음, 기준 운동일 당일과 이후 세션 무시, 기록 없음 → 빈 결과, 미리 채우기 세 경우, 입력 검증
- [x] 테스트와 빌드가 통과한다

## Comments

- 공개 인터페이스: `getPreviousRecord(exerciseId, trainingDay): Promise<PreviousRecord | null>`(`{ trainingDay, sets }`, 세트는 기록 시각 순), `getPrefill(exerciseId, trainingDay): Promise<SetValues | null>`(`{ weight, reps }`). "빈 결과/빈 값"은 `null`로 표현한다. 구현은 새 ops 파일 `src/workoutLog/previousRecord.ts`.
- 지난 기록 조회는 기존 `[exerciseId+trainingDay]` 복합 인덱스에서 `[id, minKey]`~`[id, 기준일)` 범위의 마지막 항목으로 운동일을 찾고, 그날 세트를 다시 읽는다. 스키마 변경 없음.
- 입력 검증은 `src/workoutLog/validation.ts`의 `assertValidSetValues(weight, reps)`(티켓 05와 공유, 이름·시그니처·의미 동일)로 하고 `recordSet`이 호출한다. 거부 시 저장하지 않고 reject.
- 화면: 숫자 칸은 `inputMode` 입력란 그대로 두어 탭하면 키패드가 뜬다(별도 키패드 UI 없음). +/- 는 빈 값을 0으로 보고, 무게는 0, 횟수는 1 아래로 내려가지 않는다. 화면도 기록 전에 같은 규칙으로 버튼을 비활성화해 WorkoutLog 예외가 사용자에게 닿지 않게 했다.
- 기록 후 다음 입력 칸은 방금 기록한 값으로 바로 설정한다(미리 채우기 규칙의 "당일 최근 세트"와 같은 결과라 다시 조회하지 않음). 미리 채우기는 화면 진입 시 한 번 조회한다.
- 입력 필드를 `<label>`로 감싸지 않았다: label 안에 버튼이 있으면 라벨 글자를 탭할 때 첫 버튼(−)이 눌리기 때문. 대신 input에 `aria-label`.
- "N일 전"은 두 운동일 문자열을 UTC 날짜로 바꿔 차이를 계산한다(`screens/format.ts`의 `formatDaysAgo`). 1일 전도 "1일 전"으로 표시.
- 실제 브라우저에서 화면을 직접 눌러 보지는 않았다(테스트+빌드만 확인).
