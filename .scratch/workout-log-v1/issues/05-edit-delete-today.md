# 05: 오늘 세트 수정과 삭제

**What to build:** 오늘 화면이나 기록 화면에서 세트를 탭하면 무게와 횟수를 고치거나 세트를 삭제할 수 있다. 오늘 세션의 세트를 모두 지우면 오늘 세션이 사라지고 빈 상태 안내가 보인다.

**Blocked by:** 01

**Status:** ready-for-agent

- [x] WorkoutLog가 세트 수정(무게, 횟수)과 삭제를 제공하며, 수정에도 같은 입력 검증이 적용된다
- [x] 세트를 탭하면 수정/삭제 UI가 열리고, 저장하면 오늘 화면과 기록 화면에 즉시 반영된다
- [x] 세션의 세트를 모두 삭제하면 그 세션이 조회되지 않는다
- [ ] 세트를 수정하면 미리 채우기와 지난 기록(03이 완료된 경우)도 수정된 값을 따른다
- [x] 테스트: 수정 결과 조회, 삭제 후 세션 조회, 마지막 세트 삭제 시 빈 세션 없음, 잘못된 수정값 거부
- [x] 테스트와 빌드가 통과한다

## Comments

- **공개 메서드**: `updateSet(id, { weight, reps }): Promise<void>`, `deleteSet(id): Promise<void>`(`sets.ts`). 수정 값 타입은 `SetValues`(`types.ts`). 수정 가능한 값은 무게와 횟수뿐이며 기록 시각과 운동일은 바뀌지 않는다.
- **입력 검증**: `src/workoutLog/validation.ts`의 `assertValidSetValues(weight, reps)`를 `recordSet`과 `updateSet` 모두에 적용했다(03 티켓과 같은 이름·시그니처·의미로 합의). 무게는 0 이상 유한수, 횟수는 1 이상 정수. 잘못된 수정값은 Error로 거부되고 저장된 값은 그대로다.
- **빈 세션**: 세션은 세트에서 계산되므로 마지막 세트를 지우면 `getSession`이 자동으로 `null`을 돌려준다. 별도 정리 코드는 필요 없었다(테스트로 고정).
- **미리 채우기/지난 기록 체크박스는 03에 달림**: 03의 조회가 저장된 세트에서 계산된다면 수정이 자동 반영된다. 03 병합 뒤 "세트 수정 후 지난 기록/미리 채우기가 수정 값을 따른다" 테스트를 하나 추가하고 체크하면 된다.
- **공용 UI `EditableSetList`** (`src/screens/EditableSetList.tsx`): props는 `sets`, `onChange`(저장/삭제 뒤 부모가 다시 조회). 세트를 탭하면 그 자리에서 무게·횟수 입력, 저장, 삭제, 취소가 열린다. 06 티켓의 세션 상세 화면에서 그대로 쓰면 된다.
- **화면 반영**: 오늘 화면의 종목 카드는 종목 이름 버튼(기록 화면으로 이동)과 `EditableSetList`로 나눴다. 기록 화면은 오늘 세트 목록만 `EditableSetList`로 바꿨다(위쪽 입력 영역은 03 범위라 건드리지 않음).
- **삭제 확인 창은 두지 않았다**: 스펙은 종목 삭제에만 확인 창을 요구한다. 세트는 편집 UI를 연 뒤 "삭제"를 눌러야 하므로 한 번 더 막는 단계가 있다.
- **기록 화면 입력 검증 메시지는 03 범위**: 이제 `recordSet`이 잘못된 값에 throw하므로, 기록 화면의 오류 표시는 03이 붙인다.
- **UI 확인**: 빌드와 타입 검사만 통과했고 브라우저에서 직접 눌러 보지 않았다.
